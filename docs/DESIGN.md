# 세 가지 문제와 이 앱이 하는 일

## 1. 화면 키보드로 타이핑이 힘들다

**원인**: GBoard는 손에 쥔 휴대전화를 기준으로 만든 배치입니다. 12인치대 태블릿을 세워 두고 쓰기에는
키가 작고, 숫자 줄과 Esc·Tab·화살표가 없어 문서 작업이 느립니다.

**해결**: PadDeck 키보드는 태블릿 가로 화면을 전제로 만든 노트북 배치입니다.

- 숫자 줄, `Tab`, `Esc`, 화살표, `⌫`, `⏎`가 항상 있습니다.
- `⌃ ⌥ ⌘`는 눌린 상태로 유지되어 다른 키와 조합됩니다.
- 두벌식 한글을 직접 조합하므로 GBoard 없이도 한글을 칩니다.
- 원격 화면에 연결된 상태에서는 한글 조합을 맥이 하도록 두고, 자모가 놓인 영문 키를 그대로 보냅니다.
  이렇게 해야 맥의 한글 입력기와 똑같이 동작합니다.

## 2. 애플 트랙패드가 아이패드처럼 굴러주지 않는다

**원인**: 매직 트랙패드는 표준 마우스 신호를 보내지 않습니다. macOS와 iPadOS는 애플 전용 신호를
해석해 커서 이동, 두 손가락 스크롤, 세 손가락 제스처, 관성 스크롤을 만듭니다.
안드로이드에는 이 해석기가 없습니다.

- 커널에 `hid-magicmouse` 드라이버가 있으면 마우스로 인식되어 커서와 두 손가락 스크롤까지만 됩니다.
- 없으면 블루투스로 붙어도 아무 신호가 오지 않습니다. 앱이 받을 입력 자체가 없는 상태입니다.

**해결**: 앱이 입력을 직접 붙잡을 수 있는 곳에서는 해석기를 앱이 대신합니다.

- 원격 화면에서 **마우스 잡기**를 누르면 안드로이드가 마우스 이동과 스크롤을 앱에 직접 보냅니다.
  이때 PadDeck이 이동량을 가속하고, 두 손가락 스크롤·오른쪽 클릭·세 손가락 제스처를 만듭니다.
- 커서가 화면 밖으로 나가지 않고, 탭해서 클릭, 두 번 탭하고 끌기로 드래그가 됩니다.

**한계**: 안드로이드 홈 화면이나 다른 앱 안에서는 운영체제가 포인터를 소유합니다.
앱이 그 입력을 가로챌 수 없으므로, 그 영역의 느낌은 커널과 안드로이드 설정이 결정합니다.
`tools/probe-device.sh`로 트랙패드가 인식되는지 먼저 확인하세요.

## 3. 기본 VNC가 뻣뻣하다

**원인**: 흔히 쓰는 VNC 앱은 터치를 절대 좌표로 바로 보냅니다. 커서가 손가락을 따라다니고,
스크롤·오른쪽 클릭·드래그에 해당하는 동작이 없습니다.

**해결**: RFB 3.8 클라이언트를 직접 구현했습니다.

- 상대 이동 트랙패드 방식이라 커서가 손가락에 붙어 다니지 않습니다.
- 두 손가락 스크롤은 맥의 휠 이벤트로, 두 손가락 탭은 오른쪽 클릭으로 보냅니다.
- 세 손가락 위/아래/좌/우는 `⌃↑`, `⌃↓`, `⌃←`, `⌃→`로 보내 미션 컨트롤과 데스크톱 전환을 씁니다.
- 화면은 ZRLE·Hextile·Raw를 협상하고, 맥 해상도가 바뀌면 자동으로 따라갑니다.
- 맥의 내장 화면 공유 서버에 그대로 붙으므로 맥에 따로 프로그램을 설치하지 않습니다.

## 구조

```
태블릿 ── RFB(TCP 5900) ── 맥 화면 공유 서버
  │                          │
  ├ 트랙패드 엔진 → 포인터 이벤트
  └ 키보드 → 키심 이벤트
```
